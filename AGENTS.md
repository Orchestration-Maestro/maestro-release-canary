# AGENTS.md

`maestro-release-canary` is a deliberately small Rust binary. Its only job is to prove,
on real tags, that `rust-workflows` releases what it claims: every push runs
the organization's Rust CI, and every `v*` tag runs the live release path.

## Rules

- **Keep it small.** `checked_sum` and its one dependency, `anyhow`, exist so
  the dependency policy, the SBOMs and the embedded dependency list describe
  something real. Add code only when the release path has a new case to prove.
- **Managed files belong to `rust-gate sync`.** The hooks, the lint table in
  `Cargo.toml` and the configuration files carry a `generated by rust-gate`
  marker, and the organization's quality sync rewrites them. Change their
  source in `rust-workflows`, never the copy here. The organization's rulesets
  run the Rust CI; this repository holds no caller.
- **Releases are protected.** A `vX.Y.Z` tag on `main`, an existing GitHub
  Release and two approved `release` deployments: README's "Cutting a
  release".
- **Commits** are signed, with conventional titles; `main` takes only
  squash-merged pull requests, through the merge queue: `gh pr merge --auto`
  queues a pull request once its checks pass.

## Verify before committing

```bash
rust-gate setup        # once: the organization's pinned tools and the hooks
rust-gate ci --local   # exactly what CI runs; the pre-push hook runs it too
```

`rust-gate ci --local` runs CI's checks job over the commits a push sends,
never an uncommitted change
([details](https://github.com/Orchestration-Maestro/rust-workflows/blob/main/docs/ci.md#run-ci-before-you-push)).
Done when it passes.
